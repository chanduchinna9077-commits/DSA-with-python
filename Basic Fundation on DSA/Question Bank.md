# Solution for the Linear Scan

# 🔹 Pattern: Linear Scan

Linear Scan problems are about:

* Traversing the array **once**
* Maintaining some running information
* Updating the answer dynamically
* Avoiding nested loops

Senior engineers identify Linear Scan problems quickly by asking:

> “Can I solve this while reading the array left → right exactly once?”

If yes, then:

* Use running min/max
* Use prefix/suffix information
* Use rolling sums
* Track best answer so far

This pattern appears constantly in:

* Trading systems
* Streaming analytics
* Monitoring systems
* Real-time processing pipelines

---

# 1️⃣ LC 121 — Best Time to Buy and Sell Stock

## 🔹 Block 1: Senior Insights

### Why this fits Linear Scan

You only need:

* Minimum price seen so far
* Maximum profit achievable so far

At every index:

* Either update minimum buying price
* Or calculate better profit

No need for nested comparisons.

---

### Senior Engineer Mindset

The brute force idea is:

```python
for every buy:
    for every sell:
```

That is O(n²).

A senior engineer asks:

> “Do I really need to compare every pair?”

No.

Because:

* The best buy price before today is simply the minimum so far.
* So while scanning:

  * Track minimum
  * Compute current profit instantly

---

### Interview Tips

#### Trick

Whenever the problem says:

* “maximum profit”
* “best difference”
* “buy before sell”

Think:

```text
Track minimum so far
```

---

### Complexity

We scan array once:

[
O(n)
]

Extra variables only:

[
O(1)
]

---

## 🔹 Block 2: Efficient Code

```python
class Solution:
    def maxProfit(self, prices):
        min_price = float('inf')
        max_profit = 0

        for price in prices:
            min_price = min(min_price, price)
            profit = price - min_price
            max_profit = max(max_profit, profit)

        return max_profit
```

### Complexity

* Time: O(n)
* Space: O(1)

### Interview Justification

> “Each element is processed exactly once.
> At every iteration we perform constant-time operations only, therefore time complexity is O(n).
> No auxiliary data structures are used, so space complexity is O(1).”

---

# 2️⃣ LC 53 — Maximum Subarray

## 🔹 Block 1: Senior Insights

This is classic **Kadane’s Algorithm**.

Core idea:

At each index:

* Either continue previous subarray
* Or start fresh

---

### Senior Engineer Mindset

The real question is:

> “Does previous sum help me or hurt me?”

If running sum becomes negative:

* It only decreases future sums
* So discard it

That is the entire insight.

---

### Mathematical Insight

If:

[
current_sum < 0
]

then:

[
future + current_sum < future
]

Negative prefixes are harmful.

---

### Complexity

Single traversal:

[
O(n)
]

Constant variables:

[
O(1)
]

---

## 🔹 Block 2: Efficient Code

```python
class Solution:
    def maxSubArray(self, nums):
        current_sum = nums[0]
        max_sum = nums[0]

        for i in range(1, len(nums)):
            current_sum = max(nums[i], current_sum + nums[i])
            max_sum = max(max_sum, current_sum)

        return max_sum
```

### Complexity

* Time: O(n)
* Space: O(1)

---

# 3️⃣ LC 724 — Pivot Index

## 🔹 Block 1: Senior Insights

Pivot index means:

[
left_sum = right_sum
]

Instead of recalculating repeatedly:

* Maintain running left sum
* Derive right sum mathematically

---

### Key Formula

[
right_sum = total - left_sum - nums[i]
]

This removes nested loops completely.

---

### Senior Engineer Mindset

Whenever you see:

* left side
* right side
* balance condition

Think:

* Prefix sums
* Running sums
* Mathematical rearrangement

---

### Complexity

Single pass:

[
O(n)
]

Only variables:

[
O(1)
]

---

## 🔹 Block 2: Efficient Code

```python
class Solution:
    def pivotIndex(self, nums):
        total = sum(nums)
        left_sum = 0

        for i in range(len(nums)):
            right_sum = total - left_sum - nums[i]

            if left_sum == right_sum:
                return i

            left_sum += nums[i]

        return -1
```

---

# 1️⃣ LC 167 — Two Sum II (Input Array Is Sorted)

## 🔹 Block 1: Senior Insights

### Why this fits Two Pointers

Array is sorted.

That changes everything.

Brute force:

```python id="2h9pq2"
for i:
    for j:
```

Complexity:

[
O(n^2)
]

But sorting gives order relationships.

If:

* sum too small → move left pointer right
* sum too large → move right pointer left

You eliminate huge search space instantly.

---

## Senior Engineer Mindset

The key observation:

```text id="w3bb6d"
Sorted arrays allow directional decisions.
```

Suppose:

```python id="z7q8c4"
numbers[left] + numbers[right]
```

If sum is smaller than target:

* Increasing left pointer increases sum

If sum is larger:

* Decreasing right pointer decreases sum

That is the entire optimization.

---

## Interview Recognition Trick

If you see:

* “sorted array”
* “find pair”
* “target sum”

Immediately think:

```text id="fjqfgo"
Two pointers from opposite ends
```

---

## Complexity Analysis

Each pointer moves at most n times.

So:

[
O(n)
]

Extra memory:

[
O(1)
]

---

# 🔹 Block 2: Efficient Code

```python id="6bl3b0"
class Solution:
    def twoSum(self, numbers, target):
        left = 0
        right = len(numbers) - 1

        while left < right:
            current_sum = numbers[left] + numbers[right]

            if current_sum == target:
                return [left + 1, right + 1]

            elif current_sum < target:
                left += 1

            else:
                right -= 1
```

---

## Complexity

* Time: O(n)
* Space: O(1)

---

## Interview Justification

> “Both pointers move inward monotonically.
> No pointer revisits an index, so total operations are linear.”

---

# 2️⃣ LC 11 — Container With Most Water

## 🔹 Block 1: Senior Insights

This is one of the most misunderstood Two Pointer problems.

Most beginners fail because they focus on:

* Trying every pair
* Thinking geometrically instead of logically

---

## Core Formula

Area:

[
Area = width \times min(height[left], height[right])
]

Where:

[
width = right - left
]

---

## Senior Engineer Mindset

The crucial insight:

> The shorter wall limits the water.

Not the taller wall.

So if:

* left height smaller
* moving right inward cannot help much

Why?

Because width decreases.

Only chance to improve:

* find taller shorter wall

Thus:

* move smaller height pointer

---

## Critical Observation

Suppose:

```python id="gt2k16"
height[left] < height[right]
```

Current area limited by:

```python id="i7s4yn"
height[left]
```

Keeping same left while reducing width cannot improve area.

So left must move.

This is the entire proof.

---

## Complexity

Single inward traversal:

[
O(n)
]

Constant space:

[
O(1)
]

---

# 🔹 Block 2: Efficient Code

```python id="uw4zly"
class Solution:
    def maxArea(self, height):
        left = 0
        right = len(height) - 1

        max_water = 0

        while left < right:
            width = right - left
            current_height = min(height[left], height[right])

            area = width * current_height
            max_water = max(max_water, area)

            if height[left] < height[right]:
                left += 1
            else:
                right -= 1

        return max_water
```

---

## Complexity

* Time: O(n)
* Space: O(1)

---

## Interview Justification

> “At every step one pointer is discarded permanently based on the limiting height argument, so total traversal remains linear.”

---

# Solutions for the Sliding Window Pattern problems
# 🔥 Pattern: Sliding Window

Sliding Window is one of the most important interview patterns.

A senior engineer recognizes it when:

* We need a **contiguous subarray/substring**
* We are looking for:

  * Maximum length
  * Minimum length
  * Count of valid windows
  * Longest valid segment
* Brute force checks all subarrays

Typical brute force:

```python
for i in range(n):
    for j in range(i, n):
```

Complexity:

[
O(n^2)
]

or worse.

Sliding Window reduces this to:

[
O(n)
]

by maintaining a valid window and expanding/shrinking intelligently.

---

# 1️⃣ LC 209 — Minimum Size Subarray Sum

---

## 🔹 Block 1: Senior Insights

### Why this fits Sliding Window

Problem:

Find the **smallest contiguous subarray** whose sum ≥ target.

Keywords:

* Contiguous
* Minimum length
* Positive integers

Positive numbers are the key.

Because all numbers are positive:

```text
Expanding → sum increases
Shrinking → sum decreases
```

This monotonic behavior makes Sliding Window possible.

---

## Senior Engineer Mindset

Ask:

> "Can I maintain a valid window instead of recomputing every subarray?"

Yes.

When sum becomes ≥ target:

* Window is valid
* Try shrinking it
* Keep minimizing length

---

## Recognition Trick

Whenever you see:

* Positive numbers
* Contiguous subarray
* Minimum/maximum length

Think:

```text
Sliding Window
```

immediately.

---

## Complexity

Each element:

* Enters window once
* Leaves window once

Therefore:

[
O(n)
]

Space:

[
O(1)
]

---

# 🔹 Block 2: Efficient Code

```python
class Solution:
    def minSubArrayLen(self, target, nums):
        left = 0
        current_sum = 0
        min_len = float('inf')

        for right in range(len(nums)):
            current_sum += nums[right]

            while current_sum >= target:
                min_len = min(min_len, right - left + 1)

                current_sum -= nums[left]
                left += 1

        return 0 if min_len == float('inf') else min_len
```

### Complexity

* Time: O(n)
* Space: O(1)

### Interview Justification

> Every element is added once and removed once from the window. Hence total operations are linear.

---

```python
class Solution:
    def totalFruit(self, fruits):
        left = 0
        count = {}
        max_len = 0

        for right in range(len(fruits)):
            count[fruits[right]] = count.get(fruits[right], 0) + 1

            while len(count) > 2:
                count[fruits[left]] -= 1

                if count[fruits[left]] == 0:
                    del count[fruits[left]]

                left += 1

            max_len = max(max_len, right - left + 1)

        return max_len
```

# 🔥 Pattern: Prefix Sum

Prefix Sum is used when you need to answer:

> "What is the sum of a subarray quickly?"

Instead of recomputing sums repeatedly.

---

## Core Formula

Let:

[
prefix[i] = nums[0] + nums[1] + ... + nums[i]
]

Then:

[
sum(l,r)=prefix[r]-prefix[l-1]
]

This single formula converts many O(n²) problems into O(n).

---

# 2️⃣ LC 560 — Subarray Sum Equals K

---

# 🔹 Block 1: Senior Insights

This is one of the most important Prefix Sum interview problems.

Many candidates wrongly try Sliding Window.

That fails because:

```python
nums may contain negatives
```

With negatives:

```text
Expand → sum may decrease
Shrink → sum may increase
```

Window logic breaks.

---

## Why Prefix Sum Works

Suppose current prefix sum is:

[
current
]

We want:

[
current - previous = k
]

Rearrange:

[
previous = current - k
]

This means:

> If we've previously seen prefix sum (current − k), then a valid subarray exists.

This is the key insight.

---

## Senior Engineer Mindset

Instead of searching all subarrays:

Ask:

> "How many previous prefix sums can create k?"

Use a HashMap:

```python
prefix_sum_frequency
```

Store counts of prefix sums seen so far.

---

## Recognition Trick

If you see:

* Count subarrays
* Sum equals K
* Negative numbers allowed

Think:

```text
Prefix Sum + HashMap
```

immediately.

---

## Complexity

Single traversal:

[
O(n)
]

HashMap:

[
O(n)
]

---

# 🔹 Block 2: Efficient Code

```python
class Solution:
    def subarraySum(self, nums, k):
        count = 0
        prefix_sum = 0

        freq = {0: 1}

        for num in nums:
            prefix_sum += num

            count += freq.get(prefix_sum - k, 0)

            freq[prefix_sum] = freq.get(prefix_sum, 0) + 1

        return count
```

---

## Complexity

Time:

[
O(n)
]

Space:

[
O(n)
]

---

## Interview Justification

> "Each element contributes to exactly one prefix sum update and one hash lookup, resulting in linear complexity."
